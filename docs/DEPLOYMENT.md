# Deploy AbsenInn (Firzzzy Store)

Target setup: **Supabase** (database, login, file storage) + **Render** (one Docker service that
runs the Django API and serves the frontend) + **GitHub Actions** (tests on every push, reminders
every 15 minutes). Everything has a free tier. Check the Render/Supabase pricing pages for the
current limits.

```
Browser (HP karyawan / laptop owner)
   │  https://absenninn.onrender.com
   ▼
Render: Docker ── Django + DRF ──► Supabase PostgreSQL (data, RLS)
          │  /api/*   │            Supabase Storage (selfie, lampiran — private)
          │  / (UI)   └──────────► Supabase Auth (verifikasi JWT via JWKS)
          ▼
   GitHub Actions ── CI tests · POST /api/cron/reminders/ tiap 15 menit
```

## 1. Supabase
Follow [`database/README.md`](../database/README.md) steps 1–7: run `schema.sql`, create the 4 accounts,
run `seed.private.sql`, and run the RLS tests. If you already did this in Phase 2, just paste the
**new `schema.sql`** once more (it adds migration 0005 and is safe to re-run).

## 2. GitHub
```bash
cd AbsenInn
git status                       # make sure database/seed.private.sql and .env do NOT appear
git add -A && git commit -m "AbsenInn Phase 1–9"
git remote add origin https://github.com/<username>/absenninn.git
git push -u origin main
```
The **CI** workflow (`.github/workflows/ci.yml`) runs automatically: RLS tests, the `schema.sql`
consistency check, 77 Django tests, and `check --deploy`.

## 3. Render
1. Render → **New → Blueprint** → choose the repository. Render reads `render.yaml`.
2. Fill the secret values when asked:
   | Key | Where to find it |
   |---|---|
   | `DATABASE_URL` | Supabase → **Connect** → *Session pooler* → URI (replace `[YOUR-PASSWORD]`) |
   | `SUPABASE_URL`, `SUPABASE_ANON_KEY` | Supabase → Project Settings → API Keys |
   | `SUPABASE_SERVICE_ROLE_KEY` | same page, the *service_role / secret* key — **server only** |
   | `SUPABASE_JWT_SECRET` | only for projects still on the *legacy JWT secret*; otherwise leave it empty |
   `DJANGO_SECRET_KEY` and `CRON_SECRET` are generated by Render.
3. If the service name/URL differs from `absenninn.onrender.com`, update `DJANGO_ALLOWED_HOSTS` and `FRONTEND_URL`.
4. Open `https://<service>.onrender.com/api/health/` → it should show `{"status": "ok"}`.

## 4. Frontend → production (automatic)
**Don't edit `config.js` in the repository.** It stays `MODE: 'demo'` for the public portfolio.
On Render, `FRONTEND_MODE=production` (already in `render.yaml`) plus `SUPABASE_URL` and
`SUPABASE_ANON_KEY` make the container rewrite its own copy of `config.js` at startup
(`python manage.py write_frontend_config`). So one repository gives you:

| | URL | Mode | Data |
|---|---|---|---|
| Portfolio demo | `https://<username>.github.io/<repo>/` (GitHub Pages) | demo | fictitious data in the visitor's browser |
| Real store | `https://<service>.onrender.com` (Render) | production | Firzzzy Store in Supabase |

Supabase → Authentication → **URL Configuration**: Site URL = `https://<service>.onrender.com`,
Redirect URLs += `https://<service>.onrender.com/**`. This makes password reset and employee
invitations land on your site.

## 5. Reminders (Phase 8)
Free option, GitHub Actions (`.github/workflows/reminders.yml`):
* Repository → Settings → Secrets and variables → Actions → **Secrets**: `ABSENINN_URL`
  (`https://<service>.onrender.com`) and `CRON_SECRET` (copy it from Render → Environment).
* **Variables**: `REMINDERS_ENABLED` = `true`.
* Test it: Actions → Reminders → *Run workflow* → the log shows `{"sent": {...}}`.

GitHub's scheduler can run a few minutes late. If you need exact timing, uncomment the cron job in
`render.yaml` (it's a paid Render feature) or use any external cron that sends the same POST request.

## 6. First day at the store
1. Owner logs in → Settings → *Absensi & Lokasi* → while **inside the store**, press **Gunakan lokasi saya saat ini** → Simpan.
   The radius is currently **10 m**. Phone GPS is often only accurate to 5–20 m, so employees inside
   the store may still show as "di luar radius". If that happens often, raise it to 30–50 m.
2. Payroll → *Konfigurasi Gaji* → fill in each employee's basic salary, allowances and overtime rate.
3. Employees open the site on their phone (Chrome/Safari), log in, and allow **camera** and **location**.
   Adding it to the home screen makes it feel like an app.
4. On each employee's payday (their join date): Payroll → **Hitung Payroll**
   → check the warnings → Ajukan → Setujui → transfer manually → **Konfirmasi Pembayaran**.

## Notes on free tiers
* The free Render web service **sleeps** when idle, so the first request after a while takes
  ~30–60 seconds. The reminders workflow calls it every 15 minutes from 07:00–22:00 WIB, which
  mostly keeps it awake during the day. For guaranteed speed at 08:00, use a paid instance.
* Supabase free projects pause after a long stretch of no activity. Daily attendance keeps it active.
* Backups: Supabase → Database → Backups (availability depends on the plan). Exporting a monthly
  CSV from the Reports page is a simple extra safety net.

## Alternative: frontend on Netlify/Vercel/GitHub Pages
Host `frontend/` as a static site, then set `API_BASE_URL: 'https://<service>.onrender.com/api'`.
On Render, set `SERVE_FRONTEND=False` and `CORS_ALLOWED_ORIGINS=https://<your-static-site>`.
Camera and GPS need HTTPS, which all of these hosts provide.

## Troubleshooting
| Symptom | Cause / fix |
|---|---|
| "Server API (Django) tidak dapat dihubungi" | wrong `API_BASE_URL`, or Render is asleep or still building |
| Every request returns 401 | the token can't be verified: check `SUPABASE_URL` (JWKS); legacy projects need `SUPABASE_JWT_SECRET` |
| 403 "Akun belum terhubung" | `seed.private.sql` hasn't run, or the account isn't linked (`app.link_account`) |
| Check-in "Upload foto gagal" | `SUPABASE_SERVICE_ROLE_KEY` is missing or wrong, or the `attendance-selfies` bucket doesn't exist (re-run `schema.sql`) |
| Add employee + "Buat akun login" fails | needs `SUPABASE_SERVICE_ROLE_KEY`; the invitation e-mail uses Supabase's mailer (limited on the free tier — configure SMTP in Supabase for regular use) |
| Payroll shows warnings | "hari kerja belum tercatat" → Attendance → Rekonsiliasi; "Siklus belum selesai" → calculate again after the date shown |
